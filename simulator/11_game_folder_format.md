# Game Folder Format

A complete game is a directory containing a set of ASCII map files, their accompanying
JSON files, a world graph JSON, and optional global config files. The Java engine loads
everything from this directory. The Python export script (see `tools/export_game_folder.py`)
generates this directory from the existing `.txt` terrain files.

---

## Directory layout

```
my_game/
  maps/
    map_route_1.txt
    map_route_1.json
    map_pallet_town.txt
    map_pallet_town.json
    ... (one .txt + one .json per map)
  music/
    route/        ← .flac files, randomly cycled on route maps
    town/         ← .flac files, randomly cycled on town/city maps
    cave/         ← .flac files, randomly cycled on cave/dungeon maps
    battle/       ← .flac files, randomly cycled for wild/trainer battles
    special/      ← .flac files, fixed lookups (pokecenter, gym, boss battles, victories)
    other/        ← .flac files, fallback pool for unclassified maps
  map_graph.json            ← terrain_to_ascii.py --all
  pokemon_data.json         ← tools/export_pokemon_data.py
  moves_data.json           ← tools/export_pokemon_data.py
  abilities_data.json       ← tools/export_pokemon_data.py
  exp_thresholds.json       ← tools/export_pokemon_data.py
  progression.json          (optional — engine boot generates if absent)
```

`terrain_to_ascii.py --all` produces the `maps/` directory and `map_graph.json`.
`tools/export_pokemon_data.py` produces the four Pokémon data files.
`progression.json` is not generated by the renderer.
The `music/` directory is populated from `music/` in this project root (see **Music system** below).

File naming: the map constant lowercased, preserving underscores.
`MAP_UNION_CAVE_1F` → `map_union_cave_1f.txt` + `map_union_cave_1f.json`.

## ASCII map file (`MAP_NAME.txt`)

Contains only the terrain grid. No header, no row numbers, no column ruler, no legend.
Each line is one row of tiles. Each character is one tile, matching the chars defined in
`MAP_FORMAT.md`. The grid is UTF-8 encoded.

```
████████████████████████████████
████████████████████████████████
████████████████████████████████
████████████████████████████████
████████████  ⊗      ███████████
███████████         D███████████
███████████        ⊗ ███████████
```

**Dimensions**: cols = length of the longest line (lines shorter than the longest are
padded with spaces to that length when read). rows = total number of lines. The Java
parser infers both values; no dimension header is needed.

**Encoding**: UTF-8. Multi-byte Unicode chars (≈, ♣, ►, etc.) are each exactly one
logical character and occupy one tile.

**No other content**: the file contains nothing but tile characters and newlines. Any
line that is blank (all spaces or empty) is a valid row of passable floor tiles.

## Per-map JSON (`MAP_NAME.json`)

All structured map data: warps, events, encounters, music. The ASCII grid is the sole
source of tile layout; the JSON is the sole source of everything else.

### Top-level fields

Every field listed below is present in every JSON regardless of game. Fields that produce no data for a given game are `[]` (arrays) or `null` (objects). Fields marked **[not used by simulator]** are present for completeness but the simulator does not act on them.

```json
{
  "constant": "MAP_UNION_CAVE_1F",
  "name": "Union Cave 1F",
  "game": "heartgold",
  "cols": 32,
  "rows": 96,
  "music": "cave_dark_theme_2",
  "warps": [...],
  "connections": [...],
  "elevation_addendum": [...],
  "items": [...],
  "signs": [...],
  "field_objects": [...],
  "apricorns": [...],
  "berries": [...],
  "vending_machines": [...],
  "static_encounters": [...],
  "rivals": [...],
  "coin_prizes": [...],
  "rock_smash_drops": null,
  "npcs": [...],
  "trainers": [...],
  "encounters": null
}
```

| Field | Type | Games | Simulator | Description |
|---|---|---|---|---|
| `constant` | string | all | ✓ | The map's unique identifier, matching the filename |
| `name` | string | all | ✓ | Human-readable name for display |
| `game` | string | all | ✓ | `"emerald"`, `"heartgold"`, or `"platinum"` |
| `cols` | int | all | ✓ | Grid width |
| `rows` | int | all | ✓ | Grid height |
| `music` | string | all | ✓ | Track ID from the game's music table |
| `warps` | array | all | ✓ | See `warps` section |
| `connections` | array | all | ✓ | See `connections` section |
| `elevation_addendum` | array | all | ✓ | See `elevation_addendum` section |
| `items` | array | all | ✓ | Visible and hidden item pickups |
| `signs` | array | all | ✓ | Signpost text |
| `field_objects` | array | all | ✓ | Interactive field objects (cut trees, boulders, etc.) |
| `apricorns` | array | HG | ✓ | Apricorn tree positions and colors; `[]` on EM/PT |
| `berries` | array | EM | ✓ | Berry tree positions; `[]` on HG/PT |
| `vending_machines` | array | EM, PT | ✓ | Vending machine positions and stock; `[]` on HG |
| `static_encounters` | array | all | ✓ | Pokémon on `@` tiles |
| `rivals` | array | all | — **not used** | Story rival battles (May/Brendan, Silver, Barry); `[]` when none |
| `coin_prizes` | array | all | — **not used** | Game Corner prize exchange list; `[]` when not a Game Corner |
| `rock_smash_drops` | object \| null | HG | — **not used** | Rock Smash item drop table; `null` when no drops or non-HG |
| `npcs` | array | all | ✓ | Interactive NPCs |
| `trainers` | array | all | ✓ | Trainer battles |
| `encounters` | object \| null | all | ✓ | Wild encounter tables; `null` when no encounters |

### `warps` array

Each entry is one warp tile on this map.

```json
{
  "col": 27,
  "row": 43,
  "dest": "MAP_ROUTE_32",
  "spawn_col": 14,
  "spawn_row": 142
}
```

| Field | Type | Description |
|---|---|---|
| `col`, `row` | int | Tile position of the warp on this map |
| `dest` | string | Destination map constant |
| `spawn_col`, `spawn_row` | int | Where the player appears in the destination map |

There is no `char` field — the warp's visual char is read from the ASCII grid at `(col, row)`.
Multiple warps can share a char (e.g., several `D` door tiles each going to different
destinations). Warp lookup by tile position, not by char.

### `connections` array

Border connections — walking off the edge of this map. Only present if this map has
at least one adjacent map reachable by walking off the border.

```json
{
  "direction": "NORTH",
  "dest": "MAP_ROUTE_2",
  "offset": 5
}
```

| Field | Type | Description |
|---|---|---|
| `direction` | string | `"NORTH"`, `"SOUTH"`, `"EAST"`, `"WEST"` |
| `dest` | string | Destination map constant |
| `offset` | int | Tile shift: positive = dest map is shifted right/down relative to this map's edge. The player's position at the destination = (player's perpendicular coord + offset). |

### `elevation_addendum` array

Always present. Lists bridge tiles (`=`) that have non-trivial terrain underneath.

```json
{
  "col": 15,
  "row": 13,
  "under_char": "≈"
}
```

Each entry describes what is beneath a bridge tile. Only non-trivial under-chars are
listed — a bridge tile absent from this array has passable floor (`" "`) underneath.
The `under_char` value uses the same char set as the ASCII grid (e.g. `"≈"` = water,
`"█"` = impassable wall). Used to determine if a player at water level can occupy a
bridge coordinate (e.g. surfing under a bridge).

**Default rule**: if `elevation_addendum` is empty, or a bridge tile has no entry here,
treat the space beneath it as passable floor.

### `encounters` object

```json
{
  "grass": {
    "rate": 10,
    "slots": [
      {"species": "GEODUDE", "min_level": 6, "max_level": 6, "rate": 16},
      {"species": "SANDSHREW", "min_level": 6, "max_level": 6, "rate": 16},
      {"species": "ZUBAT", "min_level": 5, "max_level": 5, "rate": 16}
    ],
    "time_overrides": {
      "morning": [
        {"species": "GEODUDE", "min_level": 6, "max_level": 6, "rate": 20}
      ],
      "day": null,
      "night": null
    },
    "swarm": "GEODUDE"
  },
  "surf": {
    "rate": 15,
    "slots": [...]
  },
  "fishing": {
    "old_rod": {"rate": 25, "slots": [...]},
    "good_rod": {"rate": 50, "slots": [...]},
    "super_rod": {"rate": 75, "slots": [...]}
  }
}
```

| Field | Description |
|---|---|
| `rate` | Base encounter rate (0–100); higher = more frequent encounters per step |
| `slots[].rate` | Relative probability weight for this slot |
| `time_overrides` | If present and non-null for a time-of-day, replaces the base `slots` during that period. `null` means use the base slots. |
| `swarm` | Species that replaces some slots during a swarm event. Null if none. |

If the `encounters` field is absent entirely, this map has no wild encounters.
If a specific method (e.g., `"surf"`) is absent from the `encounters` object, that
method has no encounters on this map.

#### `encounters.headbutt` (HeartGold only)

Present on maps with headbutt trees (outdoor routes and forests). Each slot list follows the same shape as `grass.slots`.

```json
"headbutt": {
  "common": [
    {"species": "HERACROSS", "min_level": 13, "max_level": 14},
    {"species": "AIPOM",     "min_level": 13, "max_level": 14}
  ],
  "rare": [
    {"species": "SPEAROW", "min_level": 15, "max_level": 16}
  ],
  "secret": [...],
  "tree_count": 10,
  "secret_tree_count": 0
}
```

| Field | Description |
|---|---|
| `common` | Slots for normal headbutt trees |
| `rare` | Slots for rare headbutt trees (sparser; better Pokémon) |
| `secret` | Slots for secret trees (found after game completion) |
| `tree_count` | Number of normal headbutt trees on the map |
| `secret_tree_count` | Number of secret trees; omitted when 0 |

The player headbutts a tree to trigger an encounter roll. Use `tree_count` to determine how many trees are available on the map.

#### `encounters.honey_trees` (Platinum only)

One global encounter table shared by all 21 honey trees across Sinnoh. The trees themselves appear as `"Honey Tree"` entries in `field_objects`.

```json
"honey_trees": {
  "common":   ["COMBEE", "WURMPLE", "BURMY", "CHERUBI", "AIPOM"],
  "uncommon": ["BURMY", "CHERUBI", "COMBEE", "AIPOM", "HERACROSS"],
  "rare":     ["MUNCHLAX", "MUNCHLAX", "MUNCHLAX", "MUNCHLAX", "MUNCHLAX", "MUNCHLAX"]
}
```

Each array has exactly 6 slots (indices 0–5). `null` when the encounter file is not found.

**Timing mechanic** — controlled by `HONEY_TREE_WAIT_MINUTES` and `HONEY_TREE_TOTAL_MINUTES` in `platinum_data.py` (default 6 and 24 minutes for simulator speed; real game uses hours):

| Step | Detail |
|---|---|
| Player uses Honey on a tree | Timer starts at `HONEY_TREE_TOTAL_MINUTES` |
| Wait `HONEY_TREE_WAIT_MINUTES` | Encounter becomes available; simulator shows time remaining |
| Any later check before expiry | Reports minutes still to wait, or that encounter is ready |
| `HONEY_TREE_TOTAL_MINUTES` elapsed | Tree goes bare; must re-slather |

**Group selection** (rolled at slather time):

| Group | Normal tree | Munchlax tree |
|---|---|---|
| No encounter | 10% | 9% |
| Common (Group A) | 70% | 20% |
| Uncommon (Group B) | 20% | 70% |
| Rare / Munchlax (Group C) | 0% | 1% |

Munchlax tree identity is derived from the trainer's ID (4 of the 21 trees are Munchlax trees per save file). The simulator treats all 21 trees as potentially rare-eligible.

**Slot rates within a group:** 40 / 20 / 20 / 10 / 5 / 5 (slots 0→5).

### `items` array

Both visible item balls and hidden items.

```json
{
  "col": 3,
  "row": 34,
  "name": "X Attack",
  "hidden": false
}
```

| Field | Description |
|---|---|
| `col`, `row` | Tile position |
| `name` | Item name as a display string (e.g., `"X Attack"`, `"Big Pearl"`) |
| `hidden` | `true` = hidden item (press A to find, `*` char on grid); `false` = item ball (`⊙` on grid) |

### `signs` array

```json
{
  "col": 5,
  "row": 10,
  "text": "Warning! Wild Pokémon lurk here!"
}
```

### `vending_machines` array

Vending machines on the map (Emerald and Platinum only). Each entry has a position and the list of items the machine sells.

```json
{"col": 3, "row": 2, "items": ["LEMONADE", "SODA_POP", "FRESH_WATER"]}
```

### `field_objects` array

Non-terrain objects placed on the map (cut trees, strength boulders, honey trees, etc.). Present in all three games.

```json
{"col": 12, "row": 7, "char": "♣", "label": "Cut Tree"}
```

| Field | Description |
|---|---|
| `char` | The character this object displays as on the ASCII grid |
| `label` | Human-readable label (e.g., `"Cut Tree"`, `"Honey Tree"`, `"Strength Boulder"`) |

### `apricorns` array (HeartGold only)

Apricorn trees on the map. Empty array on all other games.

```json
{"col": 8, "row": 14, "apricorn": "Pink Apricorn", "tree_index": 18}
```

| Field | Description |
|---|---|
| `apricorn` | Display name of the apricorn (e.g., `"Pink Apricorn"`, `"White Apricorn"`) |
| `tree_index` | Index into the global `sTreeApricorns[]` table |

### `berries` array (Emerald only)

Berry trees planted on the map. Empty array on all other games.

```json
{"col": 24, "row": 2, "berry_id": "BERRY_TREE_ROUTE_102_ORAN", "berry_name": "Oran"}
```

| Field | Description |
|---|---|
| `berry_id` | Internal berry tree constant from the decomp |
| `berry_name` | Display name of the berry (e.g., `"Oran"`, `"Pecha"`) |

### `static_encounters` array

Pokémon that appear at a specific `@` tile and trigger a battle when stepped on.

```json
{
  "col": 12,
  "row": 45,
  "species": "SNORLAX",
  "level": 30,
  "is_shiny": false
}
```

### `rivals` array — **not used by simulator**

Story-scripted rival battles present on the map (May/Brendan in Emerald, Silver in HeartGold, Barry in Platinum). These are fired by story scripts, not by NPC sight-line or player proximity — the simulator does not trigger them. The array is always present; `[]` when the map has no rival encounter.

Each entry has one party per starter variant (three entries on the same tile is normal for Gen 4 rivals).

```json
{
  "trainer_id": "TRAINER_RIVAL_PASTORIA_CITY_PIPLUP",
  "col": 13,
  "row": 28,
  "name": "Cedric",
  "trainer_class": "TRAINER_CLASS_RIVAL",
  "prize_money": 1800,
  "note": "Rival Pastoria City Piplup",
  "party": [
    {"species": "Staravia", "level": 34, "ivs": 80, "moves": ["Wing Attack", "Quick Attack", "Endeavor", "Double Team"]},
    {"species": "Grotle",   "level": 36, "ivs": 80}
  ]
}
```

| Field | Description |
|---|---|
| `trainer_id` | Internal trainer constant |
| `note` | Starter-variant label (e.g. `"Rival Pastoria City Piplup"`); `null` in Emerald/HG |
| `party[].ivs` | IV scale (0–255, uniform across stats) |
| `party[].moves` | Move list; omitted when using default level-up moves |

### `coin_prizes` array — **not used by simulator**

Prizes available at the Game Corner's prize exchange counter on this map. `[]` on every map that is not a Game Corner or prize exchange building. Items and Pokémon are listed together.

```json
[
  {"name": "TM90 (Substitute)", "coins": 2000, "kind": "item"},
  {"name": "Dratini",           "coins": 2100, "kind": "pokemon"}
]
```

| Field | Description |
|---|---|
| `name` | Display name of the prize |
| `coins` | Coin cost |
| `kind` | `"item"`, `"pokemon"`, or `"decoration"` (Emerald only) |

### `rock_smash_drops` object — **not used by simulator** (HeartGold only)

RNG item drops when a player smashes a rock on this map. `null` on all Emerald and Platinum maps, and on HeartGold maps with no smashable rocks.

```json
{
  "drop_chance": 10,
  "slots": [
    {"item": "Heart Scale", "probability": 10},
    {"item": "Red Shard",   "probability": 10},
    {"item": "Star Piece",  "probability": 5}
  ]
}
```

| Field | Description |
|---|---|
| `drop_chance` | Percent chance any rock smash yields an item (0–100) |
| `slots[].probability` | Relative probability of this item within the drop pool |

### `npcs` array

```json
{
  "npc_id": "NPC_HIKER_DANIEL",
  "col": 5,
  "row": 48,
  "name": "Hiker Daniel",
  "sprite": "HIKER_M",
  "facing": "SOUTH",
  "movement": "NONE",
  "is_trainer": false,
  "gives_item": null,
  "dialogue_states": [
    {
      "flag": null,
      "text": "What a surprise! I didn't expect anyone here!"
    }
  ]
}
```

Service NPCs add optional fields:

```json
{
  "service_flags": ["healer"],
  "shop_items": [
    { "item_id": "ITEM_POKE_BALL" }
  ]
}
```

Dialogue states for YES/NO prompts (healers) add optional fields:

```json
{
  "flag": null,
  "text": "Would you like to rest your Pokémon?",
  "yesno": true,
  "declined_msg": "We hope to see you again!"
}
```

| Field | Type | Description |
|---|---|---|
| `npc_id` | string | Unique identifier within the game, used for save flags |
| `sprite` | string | Sprite key referencing the NPC sprite atlas |
| `facing` | string | Initial facing direction: `"NORTH"`, `"SOUTH"`, `"EAST"`, `"WEST"` |
| `movement` | string | `MOVEMENT_TYPE_*` name with prefix stripped, e.g. `"NONE"`, `"LOOK_AROUND"`, `"WANDER_AROUND"`, `"FACE_SOUTH"`. Default `"NONE"` if absent. Gym leaders, Elite Four, and Champion always carry `"NONE"`. See `08_npc_trainers.md` for the full table. |
| `gives_item` | string or null | Item name given to player on first interaction. Null if NPC gives no item. |
| `dialogue_states` | array | Ordered from default (null flag) to most-progressed. See `08_npc_trainers.md`. |
| `service_flags` | array of strings | Optional. Lists services this NPC provides. See `08_npc_trainers.md § Service NPCs`. |
| `shop_items` | array | Optional. Present on money-based vendor NPCs; lists items as `{"item_id": "..."}` entries. |
| `exchanges` | array | Optional. Present on item-barter NPCs (`"checkitem_exchange"`, `"move_reminder"`, `"move_tutor"`, etc.). Each entry: `{"gives": "...", "receives": "..."}`. See `08_npc_trainers.md § Exchange NPCs`. |
| `trade` | object | Optional. Present on trader NPCs (`"trader"` in `service_flags`). Shape: `{"gives": "BAGON", "receives": "HORSEA", "nickname": "SEASOR"}`. `nickname` is null when the traded Pokémon has no special name. |
| `dialogue_states[].yesno` | bool | Optional. If `true`, the dialogue fires a YES/NO prompt instead of plain text. |
| `dialogue_states[].declined_msg` | string | Optional. Text shown on the NO branch when `yesno` is `true`. |

```json
{
  "trainer_id": "TRAINER_HIKER_RUSSEL",
  "col": 20,
  "row": 51,
  "name": "Hiker Russel",
  "sprite": "HIKER_M",
  "trainer_class": "HIKER",
  "is_leader": false,
  "gym_badge": null,
  "sight_direction": "SOUTH",
  "sight_range": 4,
  "prize_money": 256,
  "double": false,
  "items": [],
  "gives_item": null,
  "pre_battle": "You're headed to Azalea?",
  "defeat_text": "Oh, oh, oh!",
  "post_battle": "All right, then!",
  "last_pokemon": "",
  "half_hp": "",
  "vs_rematches": [],
  "party": [
    {"species": "GEODUDE", "level": 4, "ivs": 0},
    {"species": "GEODUDE", "level": 6, "ivs": 0},
    {"species": "GEODUDE", "level": 8, "ivs": 0}
  ]

```

| Field | Description |
|---|---|
| `trainer_id` | Unique identifier, used for `defeated_trainers` save flag |
| `is_leader` | `true` for gym leaders only |
| `gym_badge` | Badge ID awarded on defeat. Null if not a gym leader. |
| `sight_direction` | `"NORTH"`, `"SOUTH"`, `"EAST"`, `"WEST"`, or `"ALL"` (gym leaders) |

| `party[].ivs` | Single integer 0–31 applied uniformly to all IVs for this Pokémon |

## `map_graph.json`

Produced by `map_graph.py`. Format:

```json
{
  "game": "heartgold",
  "nodes": [
    {"id": "MAP_PALLET_TOWN", "name": "Pallet Town", "map_type": "TOWN"}
  ],
  "edges": [
    {
      "a": "MAP_PALLET_TOWN",
      "b": "MAP_ROUTE_1",
      "kinds": ["connection"],
      "bidirectional": true
    },
    {
      "a": "MAP_PALLET_TOWN",
      "b": "MAP_OAKS_LAB",
      "kinds": ["warp"],
      "bidirectional": true
    }
  ],
  "stats": {"nodes": 499, "edges": 535, "bidirectional": 498}
}
```

`kinds` can contain `"warp"`, `"connection"`, or both if the same map pair is connected
by both a warp and a border connection. All three games produce this format.

The Java `WorldGraph` class reads this file to build the adjacency map. It does NOT
contain per-tile warp coordinates — those come from the per-map JSON `warps` array.
The graph tells the engine which maps are reachable; the per-map JSON tells it where
the player lands.

## `progression.json`

Optional. If absent, the topological solver generates badge assignments at boot.

```json
{
  "start_map": "MAP_PALLET_TOWN",
  "start_col": 5,
  "start_row": 12,
  "elite_four_map": "MAP_ELITE_FOUR_HALL",
  "badges": [
    {"id": "B1", "gym_map": "MAP_PEWTER_CITY_GYM", "unlocks": "CUT"},
    {"id": "B2", "gym_map": "MAP_CERULEAN_CITY_GYM", "unlocks": "ROCK_SMASH"},
    {"id": "B3", "gym_map": "MAP_VERMILION_CITY_GYM", "unlocks": "SURF"},
    {"id": "B4", "gym_map": "MAP_CELADON_CITY_GYM", "unlocks": "STRENGTH"},
    {"id": "B5", "gym_map": "MAP_FUCHSIA_CITY_GYM", "unlocks": "FLY"},
    {"id": "B6", "gym_map": "MAP_SAFFRON_CITY_GYM", "unlocks": "WATERFALL"},
    {"id": "B7", "gym_map": "MAP_CINNABAR_ISLAND_GYM", "unlocks": "ROCK_CLIMB"},
    {"id": "B8", "gym_map": "MAP_VIRIDIAN_CITY_GYM", "unlocks": null}
  ]
}
```

| Field | Description |
|---|---|
| `start_map` | Map constant where the player spawns on new game |
| `start_col`, `start_row` | Player spawn tile on the start map |
| `elite_four_map` | Map constant of the Elite Four entrance hall |
| `badges[].unlocks` | HM string (`"CUT"`, `"SURF"`, etc.) or `null` if this badge unlocks nothing |

## Music system

### Source files

FLAC files from three official soundtracks, organized into six subdirectories under
`music/` at the project root. Subdirectory files are symlinks into the original
soundtrack folders; do not move or rename the source folders.

```
music/
  route/    — routes, cycling, surf, diving
```

### How music is assigned

Music is **not** stored in a catalog file — the engine assigns it at startup from the
pools in `music/`, cycling through all available tracks. No `music_catalog.json` needed.

**Randomly cycled pools** (one randomly chosen track per map, cycling through all tracks
before repeating):

| Pool | Directory | Assigned to |
|---|---|---|
| route | `music/route/` | Maps whose constant contains `ROUTE`, `ROAD`, `WATER`, `UNDERSEA`, `SAFARI` |
| town | `music/town/` | Maps whose constant contains `TOWN`, `CITY`, `VILLAGE` |
| cave | `music/cave/` | Maps whose `map_type` is `CAVE`, or constant contains `CAVE`, `TUNNEL`, `MT_`, `FOREST`, `UNDERGROUND` |
| battle | `music/battle/` | Any random wild or trainer battle |
| other | `music/other/` | Any map not matched above (fallback) |

### Startup loading

All FLAC files in `music/` are scanned and loaded at engine startup before the title
screen. **A loading bar or loading screen must be shown** during this phase — do not
drop straight into the title screen while audio resources are still loading.
The loading screen should show progress as each pool is scanned:

```
Loading music...  [■■■■■■░░░░░░░░░]  routes (41/41)
```

After all pools are built the engine proceeds to the title screen. Subsequent map loads
do not re-scan the `music/` directory.

## Topological badge solver (when `progression.json` is absent)

The engine runs this at boot to assign badges and validate the map set.

**Algorithm:**

1. Read `map_graph.json` and all per-map JSONs
2. Set `unlocked_hms = {}` (empty), `earned_badges = 0`, `reachable_gyms = []`
3. Determine `start_map`: the map whose constant contains `STARTING` or `START`, or
   the first node in `map_graph.json` nodes list if no such map exists
4. Run A* from `start_map` with current `unlocked_hms`:
   - Passability rules: same as runtime (see collision rules in `03_map_engine.md`)
   - A Pokémon trainer with `is_leader: true` is "reached" when A* finds a path to
     any tile that is orthogonally adjacent to the trainer's `(col, row)` and that
     tile is passable
   - When a gym leader is reached: award the next badge, determine which HM to unlock
     (see HM assignment below), add to `unlocked_hms`, mark gym as `earned_badges++`
   - Continue A* with updated passability
5. Repeat until no new gyms are reachable in a full pass
6. Validation:
   - If `earned_badges < 8`: BOOT ERROR — list which gyms were unreachable and which
     terrain obstacles were blocking them (chars that required unlocked HMs the
     player never got)
   - If more terrain-gating chars exist than remaining badges can unlock: BOOT ERROR —
     "Map has X unreachable areas gated by obstacles but only Y badges remain"
   - If Elite Four map is reachable only after all 8 badges (i.e., blocked by some
     terrain that requires a badge not yet assigned): log warning, not error
   - If all 8 gyms are reachable: write computed `progression.json` to the game folder
     for future boots (avoids re-running the solver)

**HM assignment during solver:**
When badge N is awarded, determine which HM to assign by testing: for each unassigned
HM in the set `{CUT, ROCK_SMASH, SURF, STRENGTH, FLY, WATERFALL, ROCK_CLIMB}`, simulate
adding it to `unlocked_hms` and re-run A* to count newly reachable gyms. Assign the HM
that unlocks the most new gyms. Ties broken by HM list order (CUT first, ROCK_CLIMB last).
If no HM unlocks any new gym, assign `null` (badge gives no HM).

**Error message format:**
```
[BOOT ERROR] Topological solver failed: only 5/8 gyms reachable.
  Unreachable: MAP_CINNABAR_ISLAND_GYM (blocked by ≈ — needs SURF)
               MAP_SAFFRON_CITY_GYM (blocked by ♣ — needs CUT, but CUT already assigned to B1)
               MAP_VIRIDIAN_CITY_GYM (no path found — disconnected from world graph)
Check map_graph.json for missing edges or per-map JSON warps for incorrect destinations.
```
